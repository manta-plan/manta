# ADR N: The decision, as a short statement

| ADR        | N                                                                                                           |
| ---------- | ----------------------------------------------------------------------------------------------------------- |
| Status     | Proposed, Accepted, Implemented, or Superseded by ADR N (linked), with its date                             |
| Decided in | the meeting, issue, or PR where it was decided, linked                                                      |
| Plan       | the plan folder while there is one, and then the plan at its last commit (omit if none)                     |

## Context

The problem and the constraints that shaped the decision, in a few sentences.

## Decision

What was decided.
If other options were considered, name each in a line, with why it was not chosen.

## Design

The services involved, what each one owns, and how they talk to each other, with a diagram if it helps.
Until the design is built, this is the plan, or a summary of it if the plan is in a folder.
Once Implemented, it describes the design as built.
Omit this section for a decision that has no design, such as the choice of a tool.

## Consequences

What gets easier, what gets harder, and which services change.
If the decision holds only for a stage, such as the MVP, say when to revisit it.
